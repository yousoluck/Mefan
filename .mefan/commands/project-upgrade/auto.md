# /project-upgrade:auto – 自动推进全流程
## 0. 日志声明（自动追加
执行本阶段所有步骤时，必须使用 `.mefan/hooks/log-event.sh` 记录日志。
- 进入阶段时：`bash .mefan/hooks/log-event.sh <阶段> <Agent> "阶段进入" "进入阶段X" "" "成功"`
- 结束阶段时：`bash .mefan/hooks/log-event.sh <阶段> <Agent> "阶段退出" "阶段X完成" "" "成功"`
- 在 Human Gate 前后记录审批事件

## 1. 角色激活
- **执行 Agent**：PM (`agents/pm.md`)，负责判断当前阶段、拉起对应 Command、断点续跑。

## 2. 前置输入
- `iterations/sprint-status.md`（含自动推进状态段）
- `iterations/mefan-log.md`（用于确认断点）

## 3. 执行流程

### 3.1 断点检查
读取 `iterations/sprint-status.md` 中的 `## 自动推进状态`：
- 若不存在该段，初始化为当前阶段=0。
- 若存在，读取 `当前阶段` 和 `已完成阶段列表`。

### 3.2 推进循环
从当前阶段开始，按序执行以下逻辑，直到阶段 6 完成：

1. **检查当前阶段是否已完成**：
   - 若在已完成列表中，跳过，进入下一阶段。
2. **拉起对应 Command**：
   - 阶段 0：触发 `/project-upgrade:00-init`
   - 阶段 1：触发 `/project-upgrade:01-requirements`
   - ... 以此类推
3. **等待阶段完成**：
   - 若阶段内包含 `[Human Gate]`，PM 等待用户输入 `APPROVED` 或 `继续`。
   - 用户确认后，PM 将本阶段标记为已完成，追加到已完成列表。
4. **更新自动推进状态**：
   - 将当前阶段+1，写入状态文件。
5. **进入下一阶段**。

### 3.3 异常处理
- 若某个阶段执行失败（日志中出现 `失败` 事件），PM 暂停推进，输出失败摘要，等待人类决策。
- 若连续失败 3 次，终止自动流程，建议手动介入。

## 4. 产出物
- 所有阶段的正常产出物
- 日志与进度报告的持续更新
