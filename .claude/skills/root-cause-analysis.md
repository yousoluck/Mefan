# 根因分析方法
- 触发条件：修复每个缺陷时（bug-log 中填写根因分析）
- 适用 Agent：开发者、QA

## 输入
- Bug 现象描述
- Bug 复现步骤
- 相关代码上下文

## 输出
- bug-log 中的"根因分析"章节填写完整
- 归类到四类根因之一：知识缺失/规则不完备/开发疏忽/技术限制

## 引入原因分类

| 分类 | 定义 | 处理方向 |
|------|------|---------|
| **知识缺失** | 开发者不知道正确做法 | 需新增 Skill 或培训 |
| **规则不完备** | 没有 Rule 覆盖此类问题 | 需新增 Rule |
| **开发疏忽** | 开发者知道但漏做 | 需加强 Hook 检查 |
| **技术限制** | 受限于现有架构/依赖 | 记录为技术债务 |

## 分析步骤

1. **描述现象**：准确描述 Bug 的表现形式
2. **回溯上下文**：查看修改历史、相关文件、引入时间
3. **确定直接原因**：代码层面是什么导致了 Bug
4. **追问"为什么"**：层层追问直到归类到四类根因之一
5. **填写 bug-log**：在根因分析章节记录完整分析过程

## 输出格式
```markdown
## 根因分析
- **现象**：[描述]
- **直接原因**：[代码层面原因]
- **根因分类**：[知识缺失/规则不完备/开发疏忽/技术限制]
- **推导过程**：[追问为什么的完整链路]
```

## 禁止事项
- 禁止跳步骤（不追问直接原因）
- 禁止填"未知"（分析必须到位）
- 禁止归类为人员失误（要归类到可改进的系统因素）
