# Iteration Planning（迭代计划）
- type: guideline
- severity: warning

## 目的

规范任务拆解标准、WIP限制设置、进度警戒线设定，确保迭代计划的可执行性和可追踪性。

## 任务拆解标准

### 拆解原则

1. **原子性**：每个任务应在2-4小时内完成（开发者视角）
2. **可验证**：每个任务有明确的完成标准，可以被测试验证
3. **独立可运行**：任务可以独立执行，不依赖其他未完成的任务
4. **关联清晰**：任务与User Story的关联明确

### 拆解检查清单

在完成任务拆解前，检查：
- [ ] 每个任务都有清晰的描述
- [ ] 每个任务都有完成标准（Acceptance Criteria）
- [ ] 每个任务都可以被测试验证
- [ ] 任务之间没有循环依赖
- [ ] 任务工时估算有依据（非拍脑袋）

### 任务与User Story的映射

```markdown
## User Story: US-001 用户登录

| 任务ID | 任务描述 | 工时(h) | 依赖 | 状态 |
|--------|---------|---------|------|------|
| T001 | 设计登录API接口 | 2 | - | Done |
| T002 | 实现登录服务层 | 4 | T001 | Done |
| T003 | 编写登录单元测试 | 2 | T002 | In Progress |
```

## WIP限制（Work In Progress）

### 设置原则

1. **安全并行数 = 团队人数 + 1**（最多多1个任务）
2. **单开发者WIP ≤ 2**（一个做，一个等）
3. **按模块WIP限制**：核心模块（认证、支付）WIP ≤ 1

### 计算公式

```
安全并行数 = min(可用开发者数, 核心模块数 × 1)
```

### 超过WIP时的处理

当任务数超过WIP限制时：
1. 暂停新任务启动
2. 完成当前任务后再启动新任务
3. PM评估是否可以并行更多任务

## 进度警戒线

### 设置方法

每个任务设置两个警戒线：
- **黄色警戒**：完成度 50% 时，进度应 ≥ 50%
- **红色警戒**：完成度 80% 时，进度应 ≥ 80%

### 警戒触发动作

| 警戒级别 | 触发条件 | 处理动作 |
|----------|----------|----------|
| 黄色 | 完成度50%时进度 < 50% | PM提醒开发者，检查是否有阻塞 |
| 红色 | 完成度80%时进度 < 80% | PM生成提案（缩小范围/延期/加资源） |

### 进度计算

```
任务完成度 = 已完成子任务数 / 总子任务数
进度偏差 = 实际进度 - 预期进度
```

## 任务状态流转

```
To Do → In Progress → In Review → Done
         ↑                        ↓
         ←←←←←←←←←←←←←←←←←←←←←←←←←
                （被打回）
```

| 状态 | 定义 | 转移条件 |
|------|------|----------|
| To Do | 任务待开始 | 开发者领取后进入 |
| In Progress | 任务进行中 | 开始实现时进入 |
| In Review | 等待Code Review | PR创建后进入 |
| Done | 任务完成 | Review通过后进入 |
| Rejected | 需要返工 | Review失败时进入 |

## 迭代计划文档要求

在 `iterations/{sprint-name}/iteration-plan.md` 中必须包含：

1. **User Story清单**：所有计划的US
2. **任务拆解表**：所有US对应的任务
3. **WIP限制**：本次迭代的WIP设置
4. **里程碑**：关键时间节点
5. **警戒线**：每个任务的警戒线设置

## 适用阶段

- 阶段3（迭代计划与任务排期）：PM拆解任务、设置WIP和警戒线
