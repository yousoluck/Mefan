# 缺陷分类标准
- 触发条件：每次发现新缺陷时（自动化测试或人工测试）
- 适用 Agent：QA、开发者

## 输入
- Bug 现象描述
- Bug 发现来源（自动化回归/人工测试等）

## 输出
- 完整的 bug-log 条目
- 严重度、类型、来源三维度分类

## 严重度分类

| 级别 | 定义 | 处理时效 |
|------|------|---------|
| **P0** | 系统崩溃、数据丢失、安全漏洞、核心流程阻断 | 立即处理，暂停其他任务 |
| **P1** | 主要功能错误、无临时绕过方案 | 24小时内修复 |
| **P2** | 次要功能错误、有临时绕过方案 | 下一个迭代修复 |
| **P3** | 建议性改进、无功能影响 | 规划中修复 |

## 类型分类

| 类型 | 说明 |
|------|------|
| 功能 | 功能不符合需求或无法正常使用 |
| 性能 | 响应时间过长、资源消耗过高 |
| 安全 | 安全漏洞、信息泄露 |
| 兼容性 | 多浏览器/多平台/多版本兼容问题 |
| UI | 界面显示问题、交互异常 |
| 文档 | 文档错误或缺失 |

## 来源分类

| 来源 | 说明 |
|------|------|
| 自动化回归 | 回归测试套件发现的缺陷 |
| 自动化集成 | 新增集成测试发现的缺陷 |
| 探索性测试 | QA 探索性测试发现的缺陷 |
| 人工测试 | 人类执行测试发现的缺陷 |

## 分类流程

1. **判断严重度**：按 P0-P3 定义判断
2. **判断类型**：按上述类型判断（可多选）
3. **判断来源**：按上述来源判断（单选）
4. **记录到 bug-log**：使用 `templates/bug-log-template.md`

## 禁止事项
- 禁止将 P0 降级为 P1
- 禁止将人工测试发现但自动化测试也应该能发现的缺陷归为"人工测试"来源
