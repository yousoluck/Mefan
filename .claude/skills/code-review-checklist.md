# Code Review 审查清单
- 触发条件：阶段 4 开发者完成 TDD 循环并提交 Code Review
- 适用 Agent：守护者

## 输入
- 开发者提交的 PR/分支
- 关联的 ADR 文档
- 一致性基线文档 `.claude/context/consistency-baseline.md`
- 需求文档 `.claude/iterations/sprint-latest/requirements/*.md`

## 输出
- Code Review 结果：APPROVED / REJECTED / CONDITIONAL
- 驳回清单（如有）
- 建议项清单（如有）

## 审查步骤

### 1. 语义正确性检查
- [ ] 代码是否实现了 ADR 描述的功能？
- [ ] 是否有遗漏的边界情况？
- [ ] 测试覆盖率是否满足质量门槛？

### 2. 安全性检查
- [ ] 是否有未验证的用户输入直接拼接到 SQL/命令？
- [ ] 是否有明文密钥或 token？
- [ ] 权限检查是否完整？

### 3. 性能检查
- [ ] 是否有循环内数据库查询？
- [ ] 是否有不必要的大对象拷贝？
- [ ] 是否有 N+1 查询问题？

### 4. 一致性检查
- [ ] 命名是否与参考模块一致？
- [ ] 错误处理范式是否与基线一致？
- [ ] 目录放置是否符合项目规范？

### 5. 可维护性检查
- [ ] 是否有可提取的重复代码？
- [ ] 函数复杂度是否过高？
- [ ] 是否有适当的注释？

## 审查结果定义

| 结果 | 条件 |
|------|------|
| **APPROVED** | 所有检查项通过 |
| **CONDITIONAL** | 有建议项，开发者可选择采纳 |
| **REJECTED** | 有阻塞项，开发者必须修复后重新提交 |

## 禁止事项
- 禁止要求与 ADR 无关的修改
- 禁止要求与一致性基线冲突的改动（除非在 ADR 中声明并审批）
